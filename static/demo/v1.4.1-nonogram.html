v1.4.1 sample fixture

A standalone sample built from the Nonogram research paper, to check the core loop before the Codex brief is written. This build is the puzzle base only — baseline rules, plus one researched genuine variant (Colour Nonogram) as a worked example. The full variant matrix comes after the base is signed off, and only from the variant research — never before it. Grid size and picture are difficulties, not variants, so they aren’t labelled as any. Every puzzle below is checked by a line solver in your browser the moment the page loads — the badge under the board is the result of that check, not a claim. All animation runs on anime.js 4.5.0, Morphi’s animation library, through one presentation-only layer — it never decides or commits a move.

Feedback mode

Switching mode keeps your grid. The research is blunt on this: classic Nonogram has no lose state at all — hearts and time penalties are inventions of specific apps, so here they are modes you opt into, never the default.

Animation — anime.js

Every animation on this page — board entrance, fill and X pops, mistake shake, hint pulse, the win reveal and the dialog — is driven by anime.js 4.5.0, the same library and version Morphi uses, called from one place only (this demo’s equivalent of src/lib/ui/motion.ts).

Presentation never commits a move. Game state changes only in the game logic; the animation layer just reflects a change that has already happened. If anime.js fails to load, or you prefer reduced motion, the animations switch off and the game plays exactly the same.

The one move that matters

Overlap: slide a run to its leftmost and rightmost legal spots — any cell covered both times is certainly filled. A clue of 8 in a row of 10 forces the middle six cells.

X-marks are logic, not decoration. Proving a cell empty is what splits a line into segments small enough to force the next fill.

How to play

  1. Each number is one run of consecutive filled cells of exactly that length, in the order shown. 3 1 means a run of 3, at least one empty cell, then a run of 1.
  2. Tap / click to fill in Fill mode. Switch to Mark X for cells you’ve proved empty — or right-click / long-press any cell to X it directly.
  3. Drag to paint a run in one stroke. A drag locks to its starting row or column, and Undo takes back the whole stroke, not one cell.
  4. A clue 0 means the whole line is empty. Clues dim when their line matches, and your current row and column stay highlighted so you never lose your place.
  5. Finish the picture to win. What “finish” means depends on the feedback mode — see the table.

Keyboard

← ↑ ↓ → move cursor · Space fill / clear · X mark X / clear · Del erase · Ctrl/⌘ Z undo · Ctrl/⌘ ⇧ Z redo. Click the board first to give it focus.

Colour Nonogram — the genuine variant. Each clue number carries a colour. Different-colour runs may sit directly against each other with no gap; same-colour runs still need at least one empty cell between them. Watch the rocket’s fins touch its body, and its orange flame touch the yellow tip — no empty cell anywhere. That one rule change rewrites the deduction, which is why it counts as a variant and a bigger grid doesn’t.

Win, lose, and what a wrong fill does

ClassicWin: every cell decided (filled or X) and all fills correct. Lose: none — the paper puzzle has no timer, lives, or penalty. Wrong fills simply sit there until logic exposes them, so Check and Hint are your safety net.
ArcadeWin: all picture cells filled (X’s optional). Lose: 3 hearts gone — a wrong fill is refused, marked with a red X, costs a heart, and stops your drag on the spot so one slip can’t burn several hearts. Modelled on Nonogram.com’s reported 3-heart system (secondary sources, not Easybrain’s own docs).
StrictWin: same as Classic. Lose: none, and no feedback at all while you play — the Wario / Time-Trial pattern. Check tells you how many cells differ, never which ones.
Picross-styleWin: all picture cells filled before the clock dies. Lose: the 30:00 countdown reaches zero. Wrong fills are refused and cost time — −2 min, then −4, then −8 each — exactly Mario’s Picross (Game Boy, 1995). Wrong X’s cost nothing, as in the original.

The fairness gate this demo runs

A puzzle can have exactly one solution and still be unfair — in Jan Wolter’s test set, 7 puzzles were unique yet needed a guess or lookahead, against 5 that solved by pure line logic. So this page runs a line solver on every puzzle at load: it repeatedly fixes any cell that is the same in every legal placement of its row and column. If that alone completes the picture, the badge says line-solvable. Deciding whether a nonogram has a solution at all is NP-complete (Ueda & Nagao, 1996), which is why the check is per-puzzle and size-bounded — and why Morphi’s generator must reject any seed the solver can’t finish, instead of shipping it as “Hard.”

Sources: Wikipedia — Nonogram · Mario Wiki — Mario’s Picross · PuzzleVuzzle — controls · EveryGameMade — uniqueness vs line-solvability · dev.to — seeded generation pipeline. Solve-time bands in the research are rough and conflicting (≈2–5 min at 5×5, ≈10–20 at 10×10, ≈25–45 at 15×15), so this demo shows your own time instead of promising one.

Variant matrix — separate step, not built into this demo

The order is fixed: global variant research first, puzzle base second, variant matrix third. Designing the matrix before the research — or before the base plays correctly — is how cosmetic reskins end up labelled as variants. So this demo ships the base and one researched variant as an example, and nothing else. The matrix itself was designed afterwards as its own document (design only, following this order), and its variants are implemented in the real build — not multiplied into this base demo.

What the global research actually found in the wild is the only starting list the matrix may draw from. It gives no total count — there is no global “how many variants are possible” number to copy. Morphi’s 100+ per type is its own design target, to be reached by designing new rule deltas in batches that pass the variant test (a variant must change matching, legal moves, available information, movement, limits or win conditions), not by counting sizes, pictures or themes.

Colour NonogramResearched — one sample built in this base. Different-colour runs may touch with no gap; same-colour runs still need at least one empty cell. The Rocket · Colour puzzle above is the worked example.
TriddlersResearched — not built. Triangular cells on a hexagonal board, clues on three axes. Waits for the matrix step; it also needs different geometry, so it is not a base feature.
TrianogramsResearched — not built. Some cells are half-filled triangles, adding cell states the line solver must handle. Waits for the matrix step.
Picross 3DResearched — not built. A prism of cubes chipped away, with count and group-count clues and a 5-strike restart in the original. A different stage shape entirely — waits for the matrix step. (“Picross” is Nintendo’s brand; the name is used descriptively here only.)
Multi-grid / MegaResearched — not built. Several small grids solved separately that combine into one large picture. Per-grid rules are unchanged, so whether it counts as a variant at all is a matrix-step decision, not assumed here.
Torus · Clue-lessUnverified — excluded. Each was found in a single source (vectree.io) with no major implementation behind it. They stay out of the matrix until verified.
Size · theme · pictureNot variants — never in the matrix. A 15×15 or a new picture is a difficulty or an instance of the same rules, per the research and Morphi’s own variant rule.
