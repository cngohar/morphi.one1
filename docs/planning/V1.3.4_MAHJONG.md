# v1.3.4 proposal — Mahjong Solitaire with variants

**Status:** Draft for owner review; implementation is not authorized by this proposal.
**Baseline:** Locally accepted v1.3.3 Member Support and accepted v1.3.2.
**Game:** Mahjong Solitaire, the solo tile-pair puzzle. This is not four-player Mahjong.

Research reference: [Mahjong Solitaire Variants](../references/puzzle-variants/Mahjong%20Solitaire%20Variants.html). This broader catalogue does not promote new features into this draft.

## Goal

Add one replayable Mahjong Solitaire family with a small set of genuinely different board variants, authoritative seeded generation/replay/scoring, and variant-specific ranked groups. Reuse the generated puzzle registry, existing variant/admin-scoring patterns, account history, shared Card shell and leaderboard infrastructure.

The existing [Mahjong Solitaire guide](../references/game-guides/Mahjong%20Solitaire%20%E2%80%94%20How%20It%20Is%20Played.html) is a mechanics reference and interactive teaching example; it is not the Morphi implementation or its approval brief.

## Proposed first variants

All use the standard Mahjong Solitaire pair-removal rules and their own variant codes and ranked score groups:

- `mahjong:turtle` — classic 144-tile, four-layer Turtle layout; the default and signature mode.
- `mahjong:quick` — compact 56-tile learning layout (14 faces, four copies each), with fewer layers and a shorter target run. The exact layout is a Morphi design choice; a commercial rules reference documents this tile count as an easy board.
- `mahjong:fortress` — 144-tile Fortress layout, offering a different layered topology from Turtle while preserving the same face set and rules.

Keep tile faces and shape semantics shared across variants. Flowers match Flowers and Seasons match Seasons; all other faces require exact matches. No wild tiles, multiplayer, daily boards, purchases, public share links, or extra variants in this proposal.

## Core play proposal

Select two currently free tiles with matching faces to remove a pair. A tile is free only when no tile covers any part of it and at least one long side has no same-layer neighbor. Clear the whole layout to win. If tiles remain and no legal matching free pair exists, the run ends as blocked. Selecting a non-matching free tile changes the selection without a penalty; selecting it again cancels.

Touch and mouse select one tile, then its match. Keyboard users move focus among free tiles and activate with Enter/Space; accessible labels identify face and availability. The board scales within the wide/full stage and remains usable in portrait, landscape and desktop layouts.

## Fairness and scoring proposal

Generation must be deterministic from the issued seed, variant and engine version, integer-only in engine core, and replayed by the server. Construct each deal by reverse-dealing pairs from an empty approved layout and retain the resulting removal sequence as a generation witness; validate the witness before issuance. A random face shuffle can produce unsolvable deals, and exact solving is computationally hard, so do not make a runtime solver the normal generation path. Server replay still validates the player's actual legal moves and score; the witness proves that the issued starting board had a solution, not that a player followed it.

Rank each variant separately. Reuse the existing per-game scoring editor/configuration and immutable score-version conventions. Proposed formula for a cleared board: `pair × pairs + clear + second × max(0, parSeconds − activeSeconds)`. Starting values for owner review: 100 points/pair, 1,000 clear bonus, 5 points/whole second under par; Quick par 180 seconds, Turtle/Fortress par 600 seconds. Thus every valid clear has a base score, and a faster clear adds a bounded time bonus. These are playtest starting values, not locked balance.

Only a fully cleared board enters the ranked leaderboard; a blocked board remains in history with pairs removed and time, but no leaderboard score. No hints, reshuffles, mismatch penalties or time penalties in this version. Invalid selections do not alter score. The server computes ranked elapsed time and score from replay; client never submits score. Each variant gets its own ranked group, so 56- and 144-tile totals are not compared against each other.

## UI and feedback proposal

Use original Morphi tile faces drawn from simple, legible symbols rather than copied game art. Preserve distinct faces without relying on color. The HUD shows tiles remaining, free-pair count and elapsed time. Help explains the free-tile rule and special Flower/Season matching. Results show score, best, pairs, time, variant and Next.

The Card opens the continuous stage; do not show a duplicate miniature board. Then the full board appears face-up in a layer-by-layer entrance: tiles rise a few pixels and settle, with rows staggered within each layer. Proposed fixed entrance allowance: 1.6 seconds for Quick, 2.5 seconds for Turtle/Fortress. Lock input until the logical active-time deadline; start solo scoring time after the entrance. Ranked timing subtracts only this server-owned fixed allowance, never a client value. No Memory-style preview is needed because all Mahjong faces are visible throughout the entrance.

A selected free tile gets a clear outline and small lift; selecting a different face gives a brief, non-punishing shake and selects the second tile. A matched pair lifts/fades away in about 180 ms; newly uncovered tiles settle and newly free edges get a brief highlight. No animation callback changes puzzle state. On win or blocked ending, the board clears/folds into the played stack, followed by the shared 420 ms fade-rise result; only the large score may use the accepted 500 ms scramble. Reduced motion settles immediately. Audio cues are original offline assets if separately approved. The puzzle-only backdrop uses Mahjong tiles only, follows the compact-hide/wide-scatter rules in `docs/puzzles/_TEMPLATE.md`, and never contains other game motifs.

## Research notes

The project's local guide correctly distinguishes Mahjong Solitaire from four-player Mahjong. External rule references agree on matching free pairs, the open-side plus uncovered condition, and separate Flower/Season groups. Existing named layouts include Turtle, Spider, Fortress and Pyramid; this proposal uses Turtle and Fortress plus a smaller teaching layout. One commercial game documents a 56-tile easy board; treat that count as a reference point, not a universal standard. Reverse-dealing gives a constructive solution witness; arbitrary face assignment risks impossible deals, while exact solving has high worst-case complexity. Sources: [rules and layouts](https://www.mahjongsolitaire.games/pages/rules), [56-tile easy board](https://mahjong.handeware.com/), [reverse-deal and solvability notes](https://www.meowjong.com/mahjong-solitaire/rules/), [complexity paper](https://arxiv.org/abs/1203.6559).
