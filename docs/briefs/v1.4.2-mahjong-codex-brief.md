## 2. Rules — from global research

Source: global Mahjong Solitaire research (9 Nov 2026). The rules below are this brief's own statements; no external file is required to build from them. Product name is **Mahjong Solitaire**. Do NOT use "Shanghai" (Activision trademark; Sunsoft claims it in Japan), "Taipei", "Kyodai", "Mahjong Titans" or "Mahjong" alone (that is the four-player game) as names. "Mahjong Solitaire" looks generic/descriptive but that is NOT legal clearance — a trademark search is still required before launch.

- **Core loop:** tap/click a free tile to select it, then a second free matching tile; both disappear, exposing tiles underneath and beside them. Repeat until the board is empty. Solo tile-pair puzzle, not four-player Mahjong.
- **Free tile — both conditions required:** (1) nothing on top — no higher-layer tile overlaps it at all; (2) left or right long side open — no same-layer neighbour on at least one side. Tiles above/below in the same layer do NOT block. Blocked tiles do not select.
- **Matching:** exact identical face, except any Flower matches any Flower and any Season matches any Season. A Flower never matches a Season. Ordinary faces have 4 copies, so which two you pair matters — a wrong pair choice can strand a solvable board.
- **Tile set:** 144 tiles = 72 pairs, 42 distinct faces: suits 108 (Circles/Bamboo/Characters 1–9 ×4), honours 28 (Winds ×4, Dragons ×4), bonus 8 (4 Flowers ×1, 4 Seasons ×1). Matching groups: 36 × 4.
- **Win:** no tiles remain. **Lose (run over):** tiles remain but no free matching pair exists and no rescue is left (Shuffle/Undo per §3). Blocked is a run over, not an invalid replay.
- **Bands (not variants, not boards):** Quick 56 (14 plain faces ×4, no Flowers/Seasons; layer 0 7×6 = 42, layer 1 7×2 = 14), Turtle 144 (layer 0, 87: rows 12, 8, 11, 13, 13, 11, 7, 12, head tile left on row 3, tail tile right on row 4; layer 1, 36: 6×6; layer 2, 16: 4×4; layer 3, 4: 2×2; layer 4, 1 centre; 87+36+16+4+1 = 144), Fortress 144 (Morphi-defined frozen layout, 3 layers, 92+40+12, 29 free at start — LOCKED by owner 2026-11-10; published Fortress counts disagree: 144 / 114 / 132 / 80 across sites, research §3). The band is drawn from the seed stream inside `createRound` (Nonogram pattern, §4), NOT a `daily_puzzle` column — that table has no band column. The only board is `(mahjong-solitaire, date)` — one identical daily puzzle per day.
- **Controls (demo-proved):** tap/click select; tap selected tile again cancels; tap a different free tile replaces the selection; keyboard Tab enters board, arrows move focus among free tiles only, Enter/Space selects, Esc clears selection, H = Hint, U = Undo, S = Shuffle, R = New deal; Hint, Undo, Shuffle, Restart (same seed, same board) buttons. Free tiles bright with teal outline + dot; blocked tiles dimmed; free-ness never shown by colour alone.
- **Demo to copy:** fixture `static/demo/v1.4.2-mahjong.html` (pre-placed by the owner from the playable demo artifact — Classic Turtle 144, Quick 56, Countdown Turtle, Avalanche Turtle, Triple Turtle 108, Fortress 144; all boards reverse-dealt with a replayed witness and a "Solvable by construction" badge). **Use the fixture as the visual and behaviour reference only — do not copy its code as production logic (demo RNG is mulberry32, not SplitMix64; demo Shuffle is unlimited in Classic; demo has no ranked timing, server replay or daily board).** If the fixture file is missing, STOP and report instead of inventing one.

## 4. Generation, determinism, fairness

- **RNG:** `createRng(seed)` (`src/lib/engine/rng.ts`, SplitMix64 v1). All draws from one stream in fixed order. Integer-only. **Banned in logic/manifest:** `Math.random`, `Date.now`, `performance.now`, `new Date`, float math (`Math.sqrt/pow/sin/...`). Enforced by ESLint + `scripts/check-boundaries.ts`; a float solver diverges across the 6 runtimes.
- **Layout data:** frozen integer half-step coordinates (`docs/puzzles/mahjong-solitaire.md` §2 + `logic.ts` `MAHJONG_LAYOUTS`). A tile is 2 units wide/tall; each higher layer is offset 1 unit in x and y so it straddles the tiles below. Free rule is computed from rectangle overlap (covered) and same-layer edge adjacency (side open), never from grid adjacency alone — higher layers are offset half a step in x and y, so they straddle the tiles below. The Turtle head/tail tiles sit within their rows (head left on row 3, tail right on row 4, §2); use the fixture's Turtle coordinates. Any layout change after release bumps the family `engine_version`.
- **Pipeline (reverse-deal):** start from the empty approved layout → repeatedly pick two (three in triple-match) currently-free positions and remove them, logging the removal order as the witness → walk the log backwards, laying one matching pair (or triple) of faces at each step (faces shuffled with the unbiased shuffle, mapped onto witness pairs, so top tiles are not systematically the same faces) → validate the witness by replaying it before issuance. Rejection sampling is deterministic if the RNG stream and accept/reject rule are identical on every platform.
- **Fairness gate (the hard rule):** a witness-validated board only — never a random face shuffle. ~2.95–3% of random Turtle deals are provably unsolvable (de Bondt, 10m deals, research §6); exact solving is PSPACE-complete (imperfect information, Condon et al. 1997) and NP-complete with peeking (de Bondt, arXiv:1203.6559), so do not put a runtime solver in the normal path. A variant witness must be checked under that variant's rules (triple witness in triples; face-down positions turned down only after a face-up witness validates; avalanche slide simulated in the witness replay). A classic pair witness does NOT certify a triple or avalanche board.
- **Band + attempts (Nonogram pattern, `logic.ts:482`):** band drawn first from the seed stream (`rng.nextInt(MAHJONG_BANDS.length)`), bands ordered quick / turtle / fortress (triple-match is exempt from the band draw and always uses the Triple Turtle 108 layout, §3); **100 attempts per band, then drop one band; if the smallest band exhausts, reject the seed and advance the RNG stream** (locked A7, §10). Require ≥1 free matching pair at deal time (no dead opening). Bound reverse-deal attempts; do not add an exact solver to the request path.
- **Move shape:** numeric-only fields only, e.g. `{tileA, tileB}` (pair) / `{tileA, tileB, tileC}` (triple) / `{tile}` (peek) / `{action}` (hint/shuffle/undo as replayed action codes, Nonogram `NONOGRAM_ACTION` pattern) — fix exact keys in `manifest.parseMove` with exact sorted-key validation like Connect (`'at,cell,pair,stroke'`). Include `at` (monotonic ms) only if a timed variant needs it. Replay regenerates the round from the seed, re-applies moves via `applyMahjongMove` (illegal move throws `RangeError`), and checks the final state is empty. The removal witness is stored for tests only — never used to judge a player's solution (Connect comment). Win is judged from player state.

## 5. Scoring, ranked integrity, ending

- **Scoring (`brief-v1`, integer coefficients ≤10000, locked A2, §10):** `score = 1000 (completion) + removals × 100 (triple removal 150) + max(0, par − seconds) × 5 − 100 × hintsUsed − 50 × shufflesUsed`, floored at 0. Par (locked A1): Quick = 180 s, Turtle/Fortress = 600 s. `brief-v1` values are admin-editable; an edit changes future rounds only, never saved scores. No standard scoring exists in the wild (research §5) — this formula is a Morphi design choice, carried from the old draft's pair 100 / clear 1000 / second 5.
- **Loss handling:** countdown timeout, three-hearts exhaustion and blocked-with-no-rescue save NO daily-board row and no score; the failed board stays viewable; ranked session marked abandoned by exact session id (Batch A precedent from Nonogram). No sixth bucket: mirror Memory's move-cap loss recording.
- **Timing floor (locked A3, §10):** manifest-owned minimum active time per band — 2,500 ms (Quick) / 10,000 ms (Turtle/Fortress). A ranked claim below the floor is downgraded to unranked, not a ban. Implemented in `saveRun` per the v1.4.1 §8B rule already in code (`runs.ts:383`: exact-millisecond comparison, below-floor saves unranked with no daily-board row, consumes the attempt, no retry, no throw). Hidden tab: checkpoint on hide, ranked time is server wall-clock (Connect pattern).
- **Ending (manifest, locked A6, §10):** `kind: 'completion'` for clear; loss variants need a variant-level `ending` override with `run_over` kind. Headlines/subline keys per `_TEMPLATE.md` ending contract; `animation: 'fade-rise'`, `continue: 'auto_500ms'` (real build only; demo stays manual — owner, 2026-11-10; Connect/Nonogram pattern — do not invent a third value). Presentation never decides end state or delays persistence.
- **Move cap (locked A4, §10):** `maxMoves` = 10,000 in the manifest. `maxSeconds` ≤7200 if present (countdown uses 600 / 180, not 1800 — the old draft's 1800 was the Nonogram countdown clock, not Mahjong's); variant `weight` 1–10000; `messages[variant.name]` must exist.
- **Leaderboard groups:** the manifest must define **no** per-variant `leaderboardGroups`. The contract already permits omitting the field (§8A). If the registry generator still requires the field at build time, that is a v1.4 refactor gap — report it, do not reintroduce per-variant groups to satisfy it.
