## 2. Rules — from global research

Source: global Nonogram research (8 Nov 2026). The rules below are this brief's own statements; no external file is required to build from them. Product name is **Nonogram**. Do NOT use "Picross" (Nintendo brand, PICROSS 3D live), "Griddlers", "Hanjie" or "Pic-a-Pix" as names. Mechanics are public domain.

- **Clues:** each row/column shows run lengths in order; ≥1 empty cell between runs; `0` = empty line. Clues are computed from the solution, never hand-authored.
- **Cells:** 3 states — unknown / filled / X. Fill = part of the picture; X = proved empty. Wrong X costs nothing.
- **Win:** all solution cells filled (X-marks need not be complete in checked modes). **Classic has no lose state** (paper rule). Lose states exist only in the two Batch A budget variants (§3).
- **Bands (not variants, not boards):** 5×5 / 10×10 / 15×15. Sizes are bands. The only board is `(nonogram, date)` — one identical daily puzzle per day.
- **Controls (demo-proved):** tap/click fill; Fill/X/Erase mode toggle; right-click / long-press X; drag locked to one row/column, undo cancels the whole stroke as one action, drag stops at first mistake in checked modes; keyboard arrows + Space fill / X mark; Hint, Check, Auto-X (toggle), Restart (same seed, same puzzle).
- **Demo to copy:** fixture `static/demo/v1.4.1-nonogram.html` (pre-placed by the owner from the playable demo artifact — 7 puzzles: 5×5 Diamond (research worked example: rows `[3],[5],[1,1,1],[3],[1]`, cols `[2],[2,1],[5],[2,1],[2]`) and Heart; 10×10 House and Rocket; 15×15 Pine Tree and Sailboat (wide test); 10×10 Colour Rocket (colour-5). Modes in demo: Classic, Arcade, Strict, Picross-style. All 7 verify line-solvable. Size/picture are difficulty, never variants. **Use the fixture as the visual and behaviour reference only — do not copy its code as production logic.** If the fixture file is missing, STOP and report instead of inventing one.

## 4. Generation, determinism, fairness

- **RNG:** `createRng(seed)` (`src/lib/engine/rng.ts`, SplitMix64 v1). All draws from one stream in fixed order. Integer-only. **Banned in logic/manifest:** `Math.random`, `Date.now`, `performance.now`, `new Date`, float math (`Math.sqrt/pow/sin/...`). Enforced by ESLint + `scripts/check-boundaries.ts`; a float solver diverges across the 6 runtimes.
- **Pipeline:** seeded picture at ~50–60% density → compute clues → verify → reject/regenerate. Rejection sampling is deterministic if the RNG stream and accept/reject rule are identical on every platform.
- **Fairness gate (the hard rule):** line-solvable only, never merely unique. Line solver = enumerate all placements per line consistent with known cells, fix cells filled/empty in ALL placements, iterate rows/columns to fixpoint. If it stalls, the puzzle needs guessing — reject the seed. Uniqueness ≠ line-solvability (Wolter set: 7 unique yet need lookahead vs 5 line-solvable). Deciding a solution exists is NP-complete (Ueda & Nagao 1996), so verify per puzzle at 5–15 sizes, where it is cheap. Cache placements per (clue, known-mask).
- **Uniqueness proof:** DFS/backtracking counting solver stopping at the 2nd solution. Bound: **100 attempts, then drop one size band (15→10→5); if 5×5 exhausts, reject the seed and advance the RNG stream** (locked). Require ≥1 line-solver step to fire on the empty board (no dead opening).
- **Variant solver:** each variant needs its own solver check (colour-aware, partial-aware, totals-aware). A full-clue pass does NOT certify a partial/totals puzzle. Smallest ambiguous case to test: 2×2 checkerboard.
- **Move shape:** numeric-only fields only, e.g. `{cell, mark}` (cell index + fill/cross/erase) — fix exact keys in `manifest.parseMove` with exact sorted-key validation like Connect (`'at,cell,pair,stroke'`). Include `at` (monotonic ms) only if a timed variant needs it. Replay regenerates the round from the seed, re-applies moves via `applyNonogramMove` (illegal move throws `RangeError`), and checks the final grid against the regenerated solution. Solution witness is stored for tests only — never used to judge a player's solution (Connect comment). Win is judged from player state.

## 5. Scoring, ranked integrity, ending

- **Scoring (`brief-v1`, integer coefficients ≤10000, LOCKED):** `score = 1000 (completion) + filledCells × 10 + max(0, par − seconds) × 10 − 50 × mistakes − 100 × hintsUsed`, floored at 0. Par (locked): 5×5 = 180 s, 10×10 = 600 s, 15×15 = 1500 s. `brief-v1` values are admin-editable; an edit changes future rounds only, never saved scores.
- **Loss handling:** countdown timeout and three-hearts exhaustion save NO daily-board row and no score; the failed board stays viewable; ranked session marked abandoned by exact session id (Batch A precedent). No sixth bucket: mirror Memory's move-cap loss recording.
- **Timing floor (LOCKED):** manifest-owned minimum active time per variant — 2,500 ms (5×5) / 10,000 ms (10×10) / 22,500 ms (15×15). A ranked claim below the floor is downgraded to unranked, not a ban. Implemented in `saveRun` per §8B: the comparison is in exact milliseconds (no flooring before the comparison), a below-floor claim is saved unranked with no daily-board row, and the saved run consumes the attempt (no retry). Hidden tab (finding recorded 2026-11-09): `visibilitychange` currently checkpoints the round and reports ranked departure when hidden; Connect pauses practice timing/presentation while ranked timing stays server-based. Nonogram follows Connect: checkpoint on hide, ranked time is server wall-clock.

Headlines/subline keys per `_TEMPLATE.md` ending contract; `animation: 'fade-rise'`, `continue: 'auto_500ms'` (Connect pattern — do not invent a third value).
