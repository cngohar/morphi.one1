## 1. Scope, Purpose and Governing Constraints

### Core Purpose
Introduce the **Tier 2 curated/observed Memory directory** in the operator admin workspace (`/admin/games?game=memory`).
As Memory expands from the 10-variant pilot toward up to 100 variants in provisional expansion batches (.8–.16), operators require a robust, searchable, filterable directory with stable cursor pagination, detailed inspection (dimensions, archetypes, policy blockers, telemetry, and rules-group scoring), and inline lifecycle actions.

Crucially, Tier 2 reconciles:
1. **Curated presets:** Defined in family code (`catalog.memory.variants`), whether active, disabled by switch, blocked by dimension policy, or never played.
2. **Observed identities:** Variants recorded in D1 history (`play_session`, `completed_run`, `account_round_activity`, or `variant_lifecycle`).

### Key Invariants
- **No traffic-only blind spots:** Curated variants that have zero plays (`shown === 0`, `played === 0`) must remain visible, findable, and manageable. Traffic-only queries must never hide newly added or disabled variants.
- **No Cartesian product materialization:** We do **not** generate all 72 hypothetical dimension combinations in the database. Only actual curated presets and observed identities are queried and displayed.
- **Bounded scale:** Query counts and payload sizes remain bounded (`O(1)` SQL queries, 10 items per page) even as the catalogue reaches 100 variants.

### Governing Constraints (C1–C10)
- **C1 (Scope/count):** Memory family only; max 100 total variants. Accepted catalogue remains the 10 pilot variants (4 original + 6 from .5). Zero new variants are added in .7. Other-family expansion is excluded; Block, Connect, and Mahjong matrices stay **UNPOPULATED**.

## 2. Directory Architecture & Data Model

### Dual-Source Directory Union
The directory synthesizes two data sources to ensure zero blind spots:
1. **Curated Presets (Code Authority):**
   - Sourced from `catalog.memory.variants` (currently 10 pilot variants).
   - Contains immutable definitions, display names, help texts, leaderboard groups, archetypes, and dimension breakdowns (`matchSize`, `opening`, `movement`, `backs`, `budget`, `availability`).
   - Every curated preset is always present in the directory, even if D1 contains zero plays or if it has never been started.
2. **Observed Identities (D1 Authority):**
   - Sourced from distinct variant strings found in D1 tables:
     ```sql
     SELECT DISTINCT variant FROM (
       SELECT variant FROM variant_lifecycle WHERE family='memory'
       UNION
       SELECT variant FROM play_session WHERE family='memory' AND variant IS NOT NULL
       UNION
       SELECT variant FROM completed_run WHERE family='memory' AND variant IS NOT NULL
     )
     ```
   - Catches historical variants, legacy variants, or uncataloged test sessions. If an observed variant is not in `catalog.memory.variants`, it is flagged with an "Observed / Uncataloged" badge.

### Filter Taxonomy
The directory supports fast, responsive multi-dimensional filtering:

| Filter Dimension | Query Key | Supported Options | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Search** | `q` | String (up to 40 chars) | `""` | Case-insensitive substring match against variant ID slug or display name. |
| **Status** | `status` | `all`, `enabled`, `disabled`, `blocked-policy`, `never-played` | `all` | `enabled`: fully active in new-round issuance.<br>`disabled`: disabled by operator switch.<br>`blocked-policy`: blocked by dimension policy.<br>`never-played`: 0 starts and 0 completions. |
| **Archetype** | `archetype` | `all`, `core`, `visibility`, `grouping`, `dynamics`, `resource`, `turn` | `all` | Matches the 6 Memory archetypes established in .6. |
| **Traffic** | `traffic` | `all`, `played`, `unplayed` | `all` | `played`: `played > 0`.<br>`unplayed`: `played === 0`. |

## 3. Stable Cursor Pagination Mechanics

### Why Cursor Pagination Over Offset Pagination?
In .2, basic offset pagination (`variant_page=0, 1...`) was implemented for the initial 4 variants. For a directory scaling up to 100 variants with dynamic filters:
- `OFFSET N` scans and discards rows, degrading performance at higher pages and drifting if records shift during concurrent session logging.
- **Keyset / Cursor Pagination** provides stable, deterministic, `O(1)` page navigation by querying relative to a unique boundary key.

### Cursor Format & Deterministic Ordering
1. **Deterministic Sort Key:** The directory orders records by `(id ASC)`:
   - Variant IDs (`memory:budget`, `memory:classic`, `memory:quads`, etc.) are globally unique slugs within the Memory family.
   - `id ASC` guarantees zero tie-break ambiguity without requiring secondary tie-breakers.
2. **Cursor Token Structure:**
   - Cursors are URL-safe base64 tokens containing:
     ```json
     {
       "after": "memory:quads",
       "dir": "next"
     }
     ```
   - Fallback clean URL parameter for direct navigation: `?after=memory:quads&dir=next` or `?before=memory:quads&dir=prev`.
3. **Boundary Query Construction:**
   - Forward page (`next`): `WHERE id > :after ORDER BY id ASC LIMIT 11` (fetches 10 items + 1 lookahead item to confirm if a next page exists).
   - Backward page (`prev`): `WHERE id < :before ORDER BY id DESC LIMIT 10` (reversed in memory to maintain ascending display).
   - Total matching count is calculated separately via a lightweight count query so operators always see: `"Showing 1–10 of 10 variants"`.

## 4. Detail Inspection, Dimension Breakdown & Scoring Links

### Inspection Drawer / Modal Elements
When an operator clicks **Inspect** on any variant row:
1. **Header & Badges:**
   - Localized Variant Title (e.g. "Quads", "Budget").
   - Slug code snippet (`memory:quads`).
   - Status Badge: `Enabled` (Green), `Disabled by Switch` (Amber), `Blocked by Policy` (Red/Muted), `Observed Only` (Blue).
   - Archetype Badge: e.g. "Extended Grouping", "Resource Pressure".
2. **Dimension Breakdown Matrix:**
   - Clear tabular display of all 6 dimensions for this variant:
     - Match Size: `4` (Quads)
     - Opening: `preview` (3s)
     - Board Movement: `static`
     - Card Backs: `uniform`
     - Attempt Budget: `standard`
     - Interactive Availability: `standard`
   - If blocked by dimension policy, highlights the exact conflicting dimension: `"Blocked by policy: matchSize = 4"`.
3. **Telemetry & Activity Counters:**
   - Exact counts: `Shown`, `Ignored`, `Played`, `Abandoned`, `Finished`, `Open`, `Imported`, `Total Completed`, `Play Rate %`.
4. **Scoring Configuration Link:**
   - Direct button/link navigating to the relevant scoring editor:
     `/admin/games?game=memory&subview=scoring#memory-quads-v1`
   - Highlights the rules group assigned to this variant (`memory-quads-v1` vs shared `memory-1`).
5. **Inline Lifecycle Controls:**
   - Enable / Disable switch directly within the drawer.
   - Disabling requires an operator reason (3–240 chars, no `@` or newlines) and confirmation checkbox.
   - Audited via `admin_audit` with `action='variant-disable' | 'variant-enable'`.

## 6. Unresolved Decisions for Owner Review

The following decisions require owner review before proceeding to visual preview and implementation:

### Decision 1: Navigation & Tab Placement
- **(Recommended) Option 1A — Dedicated Directory Tab for Memory:**
  Add a **Directory** tab to the section navigation on Memory:
  `/admin/games?game=memory&subview=directory`
  Section tabs become: `Statistics | Directory | Scoring | Policy | Settings`.
  *Rationale:* Keeps `Statistics` clean for high-level telemetry and history charts, while giving the 10–100 variant directory its own dedicated, unconstrained workspace with filters and pagination.
- **Option 1B — Replace Variants Section on Statistics Tab:**
  Keep the directory embedded at the bottom of the existing `Statistics` tab, replacing the current unfilterable variants list.
  *Trade-off:* Combines everything on one page, but requires heavy vertical scrolling past history tables on mobile viewports.

### Decision 2: Cursor Token Format & URL Strategy
- **(Recommended) Option 2A — Opaque Base64 Cursor Token:**
  Use a clean, compact URL parameter `?cursor=<token>` where the token encodes `{ after: string, dir: string }`.
  *Rationale:* Consistent with existing audit cursor (`exportAuditYear` / `v1.admin.audit.cursor`), prevents URL tampering, and encapsulates multi-field keys cleanly.
- **Option 2B — Explicit Slug Query Parameters:**
  Use human-readable query parameters: `?after=memory:quads` or `?before=memory:budget`.
  *Trade-off:* Readable in URLs, but exposes internal keyset structure directly to the address bar.

### Decision 3: Filter Toolbar Scope
- **(Recommended) Option 3A — Comprehensive Multi-Filter Bar:**
  Provide Search (slug/title) + Status (All/Enabled/Disabled/Blocked/Unplayed) + Archetype (All + 6 archetypes).
  *Rationale:* Operators can instantly drill down to "Resource Pressure" or "Blocked by Policy" variants without pagination wading.
- **Option 3B — Minimal Filter Bar:**
  Provide Search + Status filter only; omit Archetype filter.
  *Trade-off:* Simpler UI, but loses the mental grouping established in .6 Tier 1 policy.

### Decision 4: Visual Preview Fixture Gate
- **(Recommended) Yes — Preview First:**
  Build and review `static/demo/v1.3.5.7-tier2.html` at all 3 required sizes (390×844, 844×390, 1280×800) before writing any application or server code.
