## 3. Server Replay, Determinism, and Cloudflare Integrity

1. **Integer-Only Determinism:**
   - All deck layouts, workflow step retries, stream cursor steps, partition bounds, waiting room tokens, and cryptographic allowances use deterministic integer PRNG (`createRng(seed)`).
   - Zero client-only floating-point RNG.
2. **Authoritative Cloudflare / D1 Replay:**
   - Server re-executes the move sequence against the seed.
   - For `workflows-step`: server enforces 1 retry per workflow checkpoint.
   - For `ai-gateway`: server validates timestamp deltas between consecutive turns to verify 429 lockout timing integrity.
   - For `basin-catalog`: server verifies partition column boundaries for paired candidates.
   - For `privacy-pass`: server tracks cryptographic token ledger balance (`tokens >= 0`).
   - For `waiting-room`: server verifies token replenishment invariants on successful matches.
3. **Loss State Handling (Ponytail / Cloudflare best practice):**
   - Rounds ending in loss (e.g. traffic surge exhaustion or lockout) do not corrupt D1 session state or record invalid leaderboard entries.
   - Standard integer bounds and existing database tables handle all 10 variants natively without new database migrations.
