## Approved finite design matrix (not a combinatorial generator)

A preset identity requires a named baseline and **one meaningful gameplay rule/setting change**, not a new deal, color, artwork, theme, animation, timer penalty number or cosmetic board shape. These are the owner-approved supported design values for the pilot, not a schema or automatic publication rule:

| Dimension                 | Current supported behavior                                                                               | Proposed candidate behavior                                                                              | Compatibility / invalid combinations for pilot                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Match size                | Identical **2** cards; existing trios match **3**                                                        | Identical **4**                                                                                          | No pair/trio/quad hybrids in one round; quad counts and representative fixture fit are approved below, real-app fit remains unproven.     |
| Opening information       | Existing preview + hide; no-preview starts face-down                                                     | None beyond the accepted pair of opening behaviors                                                       | No new identity for a longer/shorter preview alone; preserve no-preview's zero opening allowance and the others' fixed allowance.         |
| Position after an attempt | Static in classic; existing moving shuffles only down/unmatched cards after a miss                       | Exactly two **marked** hidden cards swap on a miss; or matched cards disappear and the others close gaps | No stacking swaps, moving and collapse in pilot; all movement must be deterministic and visually/verbally traceable.                      |
| Back information          | Uniform backs; matches by symbol                                                                         | Two distinguishable backs with exactly one of each per pair                                              | Not available for trios/quads without a separately designed invariant; back pattern **constrains possible matches**, not just decoration. |
| Attempt budget            | Existing pair cap: six attempts/group; trios: six attempts/group, unfinished cap stays in play with Home | A stricter, visible **two attempts/group** cap with a proposed explicit run-over outcome                 | Budget does not stack with existing no-preview/trios/moving or other candidates; approved loss/persistence decision is below.             |
| Post-miss availability    | Any still-down unmatched card can be flipped                                                             | Temporarily block the **last flipped card for the following attempt**                                    | No lock combined with another movement/budget/size rule in pilot; lock must not prevent a legal completion.                               |

**Pilot combination policy:** the four existing presets stay exactly as they are; each proposed addition is an individually curated single-rule delta from its stated baseline. No Cartesian product, admin free-form rule editor or silent duplicate identities. Cross-axis combinations and later values are **UNSUPPORTED/UNDECIDED**, not an implied list of 90 more variants. Dimension limits live in Memory code only _if_ a later stage is authorized; policy controls may only narrow supported rules. A changed board size alone is not a variant; quads' four-cards-per-match rule is its qualifying delta.

## Earlier identity/scoring questions (resolved in approved table below)

The initial review questions are retained for context; the approved contracts below supersede their requests for decisions. Later implementation still must prove compatibility, scoring and recovery.

1. **IDs/versions:** The six `memory:*` strings above are candidates. Old omitted/explicit classic must continue to produce identical JSON/decks/hashes/replay; existing `memory-1`, `brief-v1` and `memory-trios-v1` histories cannot be reinterpreted. The current `parseRun` compares the supplied engine version with the _single live manifest version_, and ranked resume has the same check; if changing the engine version, .4 must first establish version-aware replay and session/checkpoint resolution without losing old rounds. Do **not** bump `memory-1` just by editing the manifest or retroactively reinterpret old rules. Approve exact per-preset rule/config identity and compatibility strategy in .3 before .4 work.
2. **Groups:** Current leaderboard identifiers are `memory-1:<6|8|10>` for classic and `memory-1:<variant-suffix>:<6|8|10>` for other accepted variants. Proposed additions need distinct immutable rule groups **per supported group count**; quads may need `<4|5|6>`. Do not mix separate rule identities in one leaderboard even where pair scoring coefficients are shared. Keep old histories/disabled and never-played identities inspectable. Decide group naming if the new immutable version convention changes.
3. **Scoring:** Proposal: budget/lockout/swaps/two-backs/collapse retain the existing pair coefficients as a starting point, with separate per-variant leaderboard groups; quads needs its own scoring definition and fair comparison groups. The current `scoreScope()` gives a variant a distinct scoring history only when it defines its own `scoring`; otherwise it shares the family scope. Decide whether any new rule needs an independent editable scoring scope, the quad coefficients and minimum ranked time, and whether to assign scores to losses. Never edit an accepted scoring version in place; server replay remains authoritative. No prizes or bot-proof claim.
4. **Generation/limits:** Current ten-symbol set can cover at most ten distinct groups; 6/8/10 pairs and the proposed 4/5/6 quads respect this bound. Current `MemoryRound` stores variant and only Moving's RNG-draw count, `manifest` caps moves by variant, and `CompletedRun` stores flips/seed/version; a post-miss change must replay from **accepted flips alone** and never consume the cosmetic RNG. Prove deterministic generation, no impossible deck/lock, capped moves/64 KiB payload, safe viewport fit, and reasonable ranked timing before accepting counts.
5. **Failure/recovery:** The existing unfinished trio cap is not a saved completion or result; budget's proposed run-over result would be a new behavior requiring a decision about durable local result, account history, ranked release/abandon, Next and visual presentation. Do not silently treat loss as victory or let a stale client save a nonterminal replay. Already issued rounds complete against their original immutable rules/scoring even if a later policy disables new starts.
