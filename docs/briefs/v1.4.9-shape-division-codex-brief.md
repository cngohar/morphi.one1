## 2. Rules

Family: **Shape Division** — the player is given ONE empty shape (outline only, no grid or boxes shown) and asked to cut it into N identical pieces, solving it any way they want. This is the opposite of Tangram: Tangram places already-cut pieces on a board; Shape Division CUTS the shape into the required pieces. The checker is property-based: any valid division wins; the rule decides, not one stored answer. The stored solution exists only to gate generation (§4) and to guide hints (§2 hint rule) — it is never the win condition.

| Rule | Definition (lock/decision; only the "Same size and same shape" / "Pieces must be connected" rules are owner-locked as the win rule — the rest is spec) |
|---|---|
| Win | The player cuts the shape into exactly N pieces (N from the rules), and every piece is congruent (same size AND same shape, translation/rotation/mirror as the variant allows). Any valid division wins; the rule decides, not a stored answer. Classic: N=4. |
| Lose | 3rd wrong Check ends the run (D4), or the countdown reaches 0:00 with the division incomplete (D8). There is no other lose state in Classic. A wrong Check is the only mistake source. |
| Mistake | A Check on a partition that is not a valid division (wrong piece count, pieces not equal in size, same size but not same shape, pieces not connected, gaps or overlaps) counts as ONE mistake (−50). Drafts, redraws, re-cuts and unsubmitted changes do NOT count. A wrong Check's consequence is always: the board stays exactly as the player left it (cuts remain, pieces stay detached), the mistake count advances by 1, and the player keeps playing. The 3rd wrong Check ends the run — the run is not reverted to a checkpoint and the board is not cleared. When `mistakeLimit = 0` the limit is off (Rev 3 — established meaning, Sudoku brief + Tangram/Sudoku code): a wrong Check still costs −50 but never ends the run. |
| Hint | Show-one-cell (D5): one solver-backed hint reveals one cell's piece assignment from the stored solution. −100 each, with a per-round hint cap from the config (admin-managed, §5A; default 3 in this milestone). The hint is hintUsed=true and, if the daily is solved afterwards, the daily is ranked and labelled "solved with hint". The hint must not contradict the player's current cuts: the Game chooses a cell whose assignment is consistent with the cuts already placed; if no such cell exists, the hint is refused with a plain message and costs nothing (no move logged, no deduction). The hint is deterministic from the seed (same board → same hint sequence), never from wall-clock or randomness. |
| Undo | Unlimited, free (no points), in this milestone ONLY — but LOGGED (Rev 1): an Undo step is move action 4 in the log, so replay reproduces the exact state (Rev 0 forbade logging Undo while assigning it action 4 — corrected). One tap-pair (place or remove a cut) is one Undo step; Undo reverses the last cut action only, never a Check (a mistake count and its −50 stay after an undo, §10). (Parked standing rule 2026-11-19: no unlimited undo or hints forever — undo/hints are budgets by difficulty tier, exact numbers per tier not yet specified. This build does not implement that rule. It stays in D15 as the deferred rule.) |
| Restart | −50 each (admin-managed, §5A); logged as move action 6 (Rev 1 — Rev 0 gave Restart no action code). Restart semantics (CONFIRMED at Rev 1 acceptance 2026-11-20): Restart clears all cuts (the board returns to the seeded board), resets the mistake count to 0 and removes the −50 deductions for the cleared mistakes, and preserves spent hints and their −100 deductions (`hintUsed` persists for the round; the hint cap is per round, not per restart). Restart re-cuts the same seeded board — never a re-roll. Visible countdown clock keeps time remaining against the original deadline; elapsed time does NOT reset. |
| Timeout | On the timeout action, the saver resolves the end from the run log: a timeout (countdown reached 0:00 with the division incomplete) ends the round as a completed loss — no board row, no retry, no restart of the same daily. See §5. |
| Input | Tap-two-points (D11, owner lock): faint dots mark every tappable grid point; tap a start point (teal marker + status line confirm it), tap an end point; the cut runs the straightest grid route between them, previewed live as a dashed line. A turning cut is made by tapping the corner where it turns. Corner-to-corner resolves to a stepped cut (Classic (0,0)→(4,4) = 6 edges, verified on the shipped `findCutPath` in Node, v12). Tapping the same pair again removes the cut. Each pair (place or remove) is one Undo step. A swipe counts as its two end points. Tapping a pair no grid route connects is refused at entry with a plain message ("No grid line connects those two points") — nothing is logged, no mistake is counted. Input is locked until the entrance animation completes (D17). |
| Keyboard | Arrows move a focus dot between grid vertices; Enter/Space sets the first/second point; Esc cancels a pending first point; U Undo; H Hint; R Restart; C Check. Every pointer action has a keyboard equivalent; the focus dot is visible at all times. The scheme is specified, not owner-locked (§10). |
| Check | Check submits the current partition. On Equality-score (§3A) Check is a free self-check instead (no mistake cost; only a complete 4-piece division ends the run). Check verdicts (demo text, 2026-11-19 owner screenshots): wrong piece count — "You have N pieces — the shape must be cut into exactly M"; pieces not equal in size — "Pieces are not equal in size: a, b, c, … squares"; same size but not same shape — "Pieces are the same size but not the same shape"; pieces not connected / gaps / overlaps — "Pieces must be connected with no gaps or overlaps" (specified text, follows the demo's pattern). Win header (v11): "Solved — all pieces identical!"; mistake header: "Not identical yet". |
| Detach | Free-form cutting (owner lock 2026-11-19): any closed cut detaches immediately, equal or not; Check judges equality. A detached piece lifts as a whole (outline + fill) with a 10–14 px gap (D17). Every detached piece shows its share label (e.g. 25%) — share labels are a helper on every preset in this milestone (the demo shows them on Classic and on every detached piece; the matrix's "info/helper variant" classification is preserved by §3A's naming, not by hiding the labels). The original outline stays visible as a faint ghost behind detached pieces. |
| Pieces | Pieces are grid polyominoes: connected sets of unit squares cut along grid lines. In this milestone the stored solution is always a set of connected polyominoes; the diagonal lattice (half-cell triangles) is NOT in this milestone (Diagonal dropped, §3). |
| Board | A board is a grid polyomino of 6–16 cells (Classic 12) inside a bounding box ≤ 8×8 (D12). The board is drawn as one empty outline only — no grid lines, no boxes, no cell shading. Faint dots mark tappable grid points. The board is generated from the seed (dissection-first, §4) and is identical for the same seed. |
| Daily | Daily board is `(shape-division, date)` only, Classic only (D3). Classic is the only daily-eligible preset: every other preset has `daily: false` in the manifest (`PuzzleVariant.daily`, contract.ts:33 — the issuer only considers variants with `daily !== false`, daily.ts). The daily never depends on a variant key; the daily board is graded against the Easy ladder of Classic (§4). The legacy authenticated ranked-start endpoint is additionally guarded for this family (S5, §8): a ranked start for a non-Classic preset is refused with `RunError('variant')`. |
| Unlimited | The Next button draws a random preset from the enabled set; all non-Classic presets are unlimited-only. Ranked issuance of a non-Classic preset is refused (S5, §8). Unlimited boards may be graded Medium/Hard by the preset's ladder (D9); they are never ranked. |
| Rollback | Abandon + New (Sudoku §8C(a) mechanism) applies unchanged: it abandons the issued session by exact id (`abandonRanked` sets `abandoned_at`, `ranked-session.ts:143–156`), clears the checkpoint, and returns to the normal selection flow (`abandonAndNew`, `PlaySession.svelte:798–830`, then `startRound()`). For a ranked daily the same-day attempt is SPENT — a new ranked start throws `daily_spent` (409, `ranked-session.ts:346`) — so the redeal is the next puzzle in the normal flow, NOT a replacement daily board (Rev 3 — Rev 2's "starts a fresh run on a new daily board" was wrong for a daily). For unlimited it is the next unlimited draw. An unfinished daily resumes while its session is live (`restoreChoice` resumes in place — an existing session that is not abandoned, not expired and not completed is restored by `resumableRanked`). |

| Field | Definition |
|---|---|
| Win | Any complete 4-piece division ends the run. There is no pass/fail: the run is scored by equality % (§5). A low-equality division still ends the run and still saves (score scaled by equality %); there is no fail on this preset. The only lose is the countdown (this preset is untimed by default, so in practice there is no lose state). |
| Generation | The uniqueness gate (§4) counts perfect-score divisions ONLY: exactly one fully congruent 4-piece division, plus at least one forced first placement. | Check | Check is a FREE self-check at any point (owner lock 2026-11-19, demo v9): it reports the equality % of the pieces so far, lists each piece's share, and says how many more pieces to cut (or too many). Demo v9 live probe: 3 Checks at 1 piece left mistakes 0/3; Check at 2 pieces read "42% equal" (pieces of 3 and 9 cells — see Formula); a completed division scored "Equality score: 100%", 200 points (base 1,000 − 800 hints × 100%). |

## 4. Generation, determinism, fairness

| Rule | Definition |
|---|---|
| Seed | One seed per (family, date, variant) from the daily pipeline. The daily never depends on a variant key — the daily board is `(shape-division, date)` only. Unlimited boards use the same generator with a different seed. |
| Generate | **Dissection-first, never shape-first.** Grow a random part, join congruent copies to form a board, keep the board only if it is unique (D7). A shape-first attempt (draw a shape, then search for a division) is forbidden — it produces ambiguous boards (research §5: plain symbol-free shapes rarely unique). Generation is deterministic: same seed → same board, same stored solution, same hint sequence. |
| Unique gate | Exact-cover counting with a cap of 2: count the number of valid divisions of the board into the required pieces; 0 = invalid, 1 = unique (keep), 2 = ambiguous (reject). The counter must count ALL divisions, not stop at the first. Equal-area is excepted from uniqueness (any equal-area partition counts — its stored solution is one of 6 valid partitions by design; Rev 2: "6 valid partitions" is a reference detail of the fixture board, not a production requirement — the production requirement is the §4 grade, and the fixture board fails the forced-placement leg and must be regenerated) but NOT from forced placement. Equality-score is excepted from full uniqueness (Rev 1): the gate counts only perfect-score (100% equality) divisions and requires exactly one; non-congruent complete divisions are permitted plays, not generation failures. **This gate is the hard rule of the milestone: if the generator cannot produce a unique Easy board for a preset, that preset STOPS the milestone (§3 count rule).** |
| Forced first placement | Every kept board must have at least one forced first placement (Rev 3 — pinned definition, D7): a corner cell of the board — a board cell with two perpendicular orthogonal neighbours outside the board — covered by exactly one LOCALLY legal piece placement, where locally legal means a connected piece of the preset's required piece size (and shape rule) that fits entirely within the board's cells, counted over ALL such placements, not only placements appearing in a complete solution. A count restricted to placements in a complete solution is automatic on any unique board (every cell is covered by exactly one piece in the single solution) and is not a fairness test. A board with no forced placement is rejected even if unique. This is the fairness gate (D7): the player always has a provable first move. |
| Easy ladder | Each Batch A preset has its own Easy ladder (board grades). Daily boards are always graded against Easy (D9). The ladders are per-preset because the shapes differ too much for one shared ladder (Classic 12 cells vs pieces-5 15 cells vs piece-size-4 16 cells). The tuning signal is the same across presets: generation yield (fraction of grown boards that pass the uniqueness + forced-placement gates) and exact-cover runtime. **Equal-area Easy grading (Rev 1 — the Rev 0 grade is dropped):** the Rev 0 grade (every valid partition all-straight, at least one full set of 4 strips) is impossible alongside equal-area's multiplicity — the fixture board has 6 partitions, 0 all-straight, and independent re-enumeration shows every board meeting the old grade has exactly one legal partition (351 such boards; the review's 2,649 is corrected). The revised grade: an equal-area Easy board has (i) at least one forced first placement (Rev 3 pinned definition: a corner cell covered by exactly one locally legal piece placement, counted over ALL local placements — §4 Forced first placement row), (ii) more than one valid equal-area partition, and (iii) at least one valid partition in which at most one piece is L-shaped and the rest are straight strips. All three are checked by exhaustive enumeration of the board's equal-area partitions. The fixture board meets legs (ii) and (iii) (6 partitions; its stored solution is 3 bars + 1 L) but FAILS leg (i) — verified by independent enumeration (Rev 2, partition placements) and re-verified under the corrected definition (Rev 3, local placements: 4, 5, 2, 6, 2, 6 per corner; no cell has exactly one local placement). The fixture board is therefore NOT grading evidence and must be regenerated to meet the grade. "6 solutions" is a reference detail of the fixture board, not a production requirement. The grade is feasible: independent dissection-first enumeration (Rev 2, 4,000 random-growth trials) found qualifying boards with 2, 3, 4, and 10 solutions. If the generator cannot produce a board meeting this grade, the preset STOPS the milestone. |
| Determinism | Same seed → same board, same stored solution, same hint sequence, same Easy grade. No wall-clock, no Math.random, no Date.now in generation. The generator uses the repo's SplitMix64 (`createRng(seed)`, `nextU64()`, `shuffle(rng, items)` — `src/lib/engine/rng.ts:27,56`, verified at HEAD `14ed815`). |
| Daily seed walk | The daily pipeline's existing seed walk applies unchanged (`src/lib/server/daily.ts:119–148`, verified at HEAD `14ed815`): `dailySeedOk(seed, variant)` hook + 1,000-seed walk, `daily_unavailable` (503) on exhaustion. The family's `dailySeedOk` must reject a seed whose board fails the uniqueness + forced-placement gates (and, for the daily, the Easy grade). A daily walk that exhausts its seeds yields `daily_unavailable` rather than an unsolvable or ambiguous deal. |
| Board size | 6–16 cells, bounding box ≤ 8×8 (D12). All demo boards satisfy this; the largest (piece-size-4, 16 cells, 4×7 bbox) still gives 44+ px cells at 358 px. |
| Content gate (one-tree) | A content rule is genuine only if it changes which divisions win. Generation gate (Rev 1): a content board must have exactly one valid division WITH the content rule and at least two valid divisions WITHOUT it. The fixture board for one-tree FAILS this gate as built — it has exactly one congruent division with and without its rule (verified by independent enumeration from boards.json, Rev 1) — so Codex regenerates the board under this gate; the fixture board is a reference, not a production board. The stored solution's tree placement is part of the board data. A content-free board at the same size is rarely unique (research §5) — but rarity is not a proof; the gate, not the claim, decides. Symbols (Rev 4): dropped from Batch A — no content gate applies to symbols in this milestone; the symbols fixture board is orphaned reference data. |
| Reproducibility | The exact-cover counter and the forced-placement check must be runnable in Node (no browser) so `bun run check:vectors` can verify boards without a DOM. The counter is the same code in generation and in verification — never two implementations. |
| Generation yield / runtime | UNMEASURED (open question 8, §10). The brief does not set a yield or runtime target; Codex measures and reports: exact-cover runtime at up to 48 cells (piece-size-4 is 16; the cap is 48 for later batches) and daily-seed-walk attempts average/p95. If the daily walk regularly exceeds 100 attempts, stop and report — do not silently widen the walk. |

## 5. Scoring, ranked integrity, ending

§5A defines the admin-managed settings; this section defines the code-locked scoring formula and the ranked-integrity rules. The formula below is the accepted default (D6), confirmed at Rev 0 acceptance 2026-11-20.

| Field | Definition |
|---|---|
| Formula | `score = max(200, 1000 − elapsedSeconds) − 100×hints − 50×mistakes − 50×restarts + countdownBonus`, where `elapsedSeconds` is gameplay seconds (ranked wall time minus entrance minus card opening, see Timing below), `countdownBonus` is remaining seconds ×1 on countdown presets only (0 otherwise), and the whole result is floored at 0. Points rank the board; no stars in Batch A. Equality-score preset: `score = floor(equality% × standard score)` (§3A). |
| Completion | 1,000 points for a completed division. |

**Move shape (SPECIFIED, not owner-locked):** a move is `{action, first, second}` where `action` is 0 = place cut, 1 = remove cut, 2 = check, 3 = hint, 4 = undo, 5 = timeout, 6 = restart (Rev 1 — Rev 0 gave Restart no code); `first`/`second` are grid-point vertex indices (row-major over the board's bounding-box grid) for cut actions, and 0 for non-cut actions. `parseMove` validates shape/keys only — it rejects any key other than the exact set `'action,first,second'`; board-specific vertex validation (indices in range, routable pair) belongs in replay (`applyShapeDivisionMove`), not in `parseMove` (Rev 1). A tap-pair that no grid route connects is refused at entry (never logged, §2). A cut action whose route is null is refused at entry. The move log is the replay source: replaying the log from the seed must reproduce the exact board state (cuts, detached pieces, mistakes, hints, restarts, score).
