Connect Puzzle Variants

A catalogue of named, published pair-connecting path games and modes — the Flow Free / Numberlink family — that change a rule compared with Morphi's Connect base: connect every pair to win, filling the grid only a bonus, and crossing a foreign path cuts it. 26 entries are listed: 18 verified and 8 flagged. Collapsing same-dimension duplicates leaves 13 distinct path-rule systems, plus one meta ending system. Research only — no variant pick or build is made here.

The base every variant is measured against

The comparison base is Morphi's Connect game as stipulated for this research. Every rule change in the catalogue is stated relative to it — connect-all win, fill as bonus, cut-on-cross, square grid, two endpoints per pair, no walls or holes.

The base game

  • Connect matching pairs of endpoints with paths on a square grid; paths cannot share cells.
  • A path cannot cross a foreign path — crossing one cuts it.
  • Win: every pair connected. Filling every cell is not required — it is an optional score bonus.
  • Bands: 5×5 with 5 pairs · 6×6 with 6 pairs · 7×7 with 8 pairs — each round timed.
  • Score rewards connected pairs and the full-grid bonus, rewards beating par time, and penalises redraws.

A solved 5×5 Flow-style board: five pairs joined, every cell covered. Under Morphi's base rules the full cover is a score bonus — the win is the five connections.

The central discrepancy — Flow Free's own win rule is unsettled in the sources. Three readings coexist. (i) The publisher's slogan — “Pair all colors, and cover the entire board to solve each puzzle” — makes fill-all the win. (ii) Fan-wiki tips, repeated across pack pages, say a level is not complete without full fill, and locked packs will not unlock the next level. (iii) The fan wiki's mechanics page describes three endings — creating all flows without filling all squares, filling all squares over the minimum moves, or finishing with a star — implying connect-only does finish a level (a checkmark), while full fill in fewest moves earns the star.

The most consistent reconciliation: connect-only = level marked complete but not “perfect”, while the store slogan collapses complete and perfect into “solve”. This was not resolved by a live app check — the research was signed-out and index-based — so Morphi's stated rule (connect-all = win, fill = bonus) is treated as matching reading (iii), not reading (i). Any comparison that says “Flow Free requires fill-all” without this caveat overstates the case.

Counting convention

A named published game or mode is counted once, and only if it changes a rule versus the base — never for art, theme, colour scheme, soundtrack, board size alone, or pair count alone. Same-dimension duplicates stay in the full list of 26 but are collapsed in the core count of 13. Combinations are not published games. Status: Verified = a solid source (publisher, Wikipedia, a paper or thesis, a reputable puzzle site, or — for its own game — the developer's own detailed site); Flagged = the rule rests on a store blurb, a forum post or single wiki line, or a contradictory blurb. All sources were read on 2026-11-04.

Rule dimensions — what actually varies

Ten dimensions were checked across the catalogue, plus further dimensions the research found along the way. Values are given verified first; values marked † appear in wish-lists and briefs but were not found as a published Flow-family rule in this research.

Grid geometry / adjacency
Square, 4-neighbour (base) · hexagonal, 6-neighbour (entry 3) · triangular, 3-neighbour (entry 13) · mixed cell shapes + round edges (entry 5) · irregular outline via absent cells (entry 7). † A torus is really entry 4's topology, not a cell shape. † Diagonal movement: not found.
Win condition
Connect all pairs only (entry 9's connect-only reading; the Morphi base) · fill all playable cells (entries 1, 3–5, 20–22) · fill-all + fewest moves = a “perfect” star, vs a plain checkmark for completion (entries 1, 8). † Fill a target percentage (e.g. 80%) as a win: not found — Morphi's fill-as-bonus is a scoring variant of this idea, not a published win rule found here.
Crossing rule
Forbidden — and the interaction on conflict differs by implementation: Morphi cuts the foreign path, while Flow's fan-wiki mechanics describe drawing over a filled square as truncating / overwriting that flow at that point · allowed at bridge cells (entry 2) · avoided via teleport instead of crossing (entries 4, 21). † Free crossing anywhere: not found.
Topology / wrap
None (planar board) · edge-to-opposite-edge wrap (entry 4) · interior paired portals (entry 21). † Klein-bottle or other topologies: not found.
Obstacles
None · edge-walls blocking adjacency (entry 6) · absent / unfillable cells (entry 7). † Moving blockers: not found — Dot Knot Chain's “moving nails” (entry 19) is a flagged, contradictory blurb, and describes pins in a rope game, not verified Flow obstacles.
Path constraints
None beyond no-share / no-cross — zig-zags allowed (entries 1, 12) · minimum-turns / no-U-turn (entry 11) · one-way / directed edges (entry 20) · must-visit waypoints (entry 22). † Single-stroke-per-colour as a rule (rather than an input method): not found. † No-backtracking: not found as a distinct rule. † Length limits: not found. † A no-touching / adjacency ban between different colours: not found — different colours routinely sit adjacent in Flow solutions.
Endpoint rules
Exactly 2 per colour in the base and every verified game — colour is the pair identity. † More than 2 per colour: only the flagged Triple Dots (entry 17). † Endpoints that move: not found. † Endpoints visited in a required order: not found — Circuit Trace's checkpoints state no order (entry 22). † Two pairs sharing one colour: not found.
Branching
Forbidden everywhere in verified games — a path is a simple path: endpoints have degree 1, interior cells degree 2. A triple-endpoint “path” that branches would be a tree, not a path — which is why entry 17, if verified, is a genuinely new topology, not a parameter.
Helpers / assists
Hints — Flow: limited, buyable or ad-watched; Dot Knot: a hint shows one colour's full path; Circuit Trace: a hint shows the full next line of the last-touched colour · undo — Flow's undo button, and tapping a dot clears that flow · restart to retry for a perfect star. A “check” mistake-checker: not found as a named feature — the checkmark is a completion mark, not a checker. Shuffle: not found — shuffling endpoints would change the puzzle, not assist solving it.
Ending / scoring / delivery
Free-play level packs (sequential, some locked) · Time Trial — most boards in a fixed time (entry 8) · Circuit Trace's 60-second Time Trial and Endless procedural chaining · Daily / Weekly puzzles with streaks (delivery, not a rule) · star (perfect, fewest moves) vs checkmark (completed) (entry 1). Morphi-style par-time + redraw-penalty scoring is a Morphi choice, not a published Flow rule found here — Flow's perfect is fewest moves, not fewest redraws or a par time.
Also found
Interaction semantics on conflict — cut vs truncate / overwrite (see crossing) · solution uniqueness — Numberlink's “well-designed” criterion; a design rule for which boards count, not a play rule · board generation — handcrafted vs procedural / endless (Circuit Trace) vs daily-seeded · endpoint marking — colour vs number vs letter vs animal icon is presentation, not a rule (entries 9, 10 collapse on it) · folk heuristics that are not rules — e.g. the fan wiki's “2×2 pools are not intended, so pretend they are illegal” is a solving tip, not a published rule, and is not counted.

The conservative core — 13 path-rule systems

Collapsing same-dimension duplicates and dropping all eight flagged entries leaves 13 distinct path-rule systems. Time Trial (entry 8) is a 14th system of a different kind — a meta ending that layers over any path system. Sensitivity note: if Shapes (entry 5) is held to subsume pure triangular boards, the core falls to 12; the 13-count keeps them separate because Shapes is documented as mixed shapes and round edges, not a pure triangular grid. Of the flagged entries, Triple Dots (entry 17) is the only one that would add a 14th path system if independently verified.

Data-only vs new mechanics

Relative to the Morphi base, and assuming the generator is graph-based — cells as nodes, steps as edges, as Flow solvers treat boards (see the Flow solver model) — these variants split into parameters the existing generator could in principle express, and rules that would need new mechanics code.

Data-only — parameters, no new path mechanics

  • Grid shape among square / hex / triangular / mixed boards, if the generator already stores an adjacency graph — the board is then a different node/edge list plus cell-shape artwork. Rendering new shapes is asset work, not a path rule.
  • Win flag: connect-all vs fill-all — a boolean win predicate over the same paths. Fill-as-bonus is already Morphi's scoring.
  • Obstacle map: edge-walls are deleted edges; absent cells are deleted nodes — Worm, Inkblot and Scattered boards are just a subset of nodes.
  • Plain parameters: board size, pair count, endpoint placement, timer / par values, star thresholds, hint availability, undo on/off, and level-pack vs endless vs daily delivery.
  • Minimum-turns as a score (counting turns) — but enforcing it as a win rule belongs in the other column.

New mechanics — code, not data

  • Bridges (entry 2): a cell must hold two paths at once — one over, one under — with a layer/order state. The one-path-per-cell invariant the base relies on must break at bridge cells only, and crossing be legal only there.
  • Edge-warps (entry 4): adjacency wrapping across edges is cheap as data, but path rendering and input that continue across the edge are UI / mechanics work, not a board file.
  • Interior portals (entry 21): paired teleport nodes with a pairing table; a path is no longer a contiguous chain of adjacent cells.
  • One-way diodes (entry 20): directed edges plus a direction check on every step, including forbidding entry from the wrong side — path validation becomes directed.
  • Must-visit stars / checkpoints (entry 22): an extra win predicate — every waypoint visited by the correct colour's path (in order, if ordered) — plus generation that guarantees a waypoint lies on its colour's path.
  • Triple endpoints (entry 17, flagged): a colour's solution becomes a path through a middle terminal, or a branching tree; endpoint-degree and win checks change.
  • Minimum-turns as a win rule (entry 11): the published rule is “fewest turns given the other paths” — enforcing it means comparing against alternative routes around those paths, not just counting turns, and the source itself notes no formal definition was found.
  • Moving endpoints, moving blockers, ordered endpoints: a time-stepped board state with re-validation after every move — and no verified published example was found to copy.
  • Interaction semantics: Morphi already implements cut-on-cross; Flow's truncate-on-overdraw is a different undo / overwrite behaviour — input-handling code, not board data.

Boundary games — close relatives, not variants

These sit next to the family — pipes, loops, dots, circuits — but are not pair-connecting path variants under the strict rule, and are not counted.

Uncertainties, gaps & what was not counted

Discrepancies & open questions

  • Flow Free's win rule: the three-way discrepancy set out at the top of this page — publisher slogan vs fan-wiki tips vs fan-wiki mechanics. Unresolved by any live app check; Morphi's rule is treated as matching the connect-only-with-checkmark reading.
  • Bridges orientation: sources agree crossing is allowed only at bridges, but one review's description is garbled (“one line must pass through the bridge vertically, while another needs to go through it vertically”) — the one-vertical, one-horizontal reading is inferred, not quoted. Fan-wiki level data shows 1–3 bridges per level; whether every level has exactly the bridges it needs, vs optional bridges, is not stated.
  • Warps vs portals: Wikipedia and the fan wiki describe Warps as edge-to-edge only; Circuit Trace's portals are interior paired cells. Different mechanics sharing the word “warp / portal” in secondary coverage — entries 4 and 21 must not be merged.
  • Shapes “3D” claim: secondary solver / SEO pages claim “three-dimensional puzzle elements” and “skyscraper” packs for Shapes; the publisher and Wikipedia say only multiple cell shapes and round edges. The 3D element is treated as unverified embellishment and is not counted.
  • Numberlink's own fill rule: Wikipedia calls unique + filled the “well-designed” standard while noting some designers do not stipulate it; the academic paper footnotes that the coverage constraint is absent from Nikoli's own Numberlink page, possibly by omission. Even the paper game's rule is ambiguous — the connect-only vs fill-all split here reflects the sources, not a settled ruling.
  • Minimum-turns definition: the academic source's authors state they have not seen a formal definition, and interpret it as fewest turns within the path's homotopy class. Any use of entry 11 would implement an interpretation, not a canonical rule.
  • Circuit Trace is single-source: entries 20–22 rest entirely on the developer's own site — detailed and internally consistent (modes, counts, editor, hints), but no independent review or store page confirming the diode / portal / star rules in play was found. Verified-primary, not independently corroborated.
  • Stars vs checkpoints: Circuit Trace lists both words but never defines whether a star is collected by any colour, must sit on a specific colour's path, or must be visited in order. Collapsing them into one must-visit system is the conservative choice; they could be two systems.
  • Dot Knot Chain (entry 19): its own page simultaneously claims bridges and intersecting lines and a no-intersects win condition, plus timed / limited-move / rope-sorting language that reads like a different game pasted in. Nothing about it should be relied on.
  • Size → colour mappings conflict: Wikipedia gives Flow's range as 5×5 (3 colours) to 15×15 (up to 16); fan-wiki pack pages give different colour counts for the same sizes. Sizes and counts are parameters, so the core is unaffected — but no single size-to-colour mapping should be quoted as canonical.

Not counted, and what was not found

  • Parameters, delivery and art only: Mania packs (board size only); Jumbo / Mega Mania / Jumbo Rectangle / Tower (large or rectangular sizes only); Rainbow / Pink / Purple / Dark Matter packs (colour and theme only); Regular / Bonus / Extreme packs (difficulty and size only); the Bridges / Hexes / Warps / Shapes sampler packs inside the original Flow app (the same systems as entries 2–5, ported as packs); Daily / Weekly puzzles (a delivery schedule plus streaks, no rule change); colour labels for colour-blind play (accessibility marking, not a rule); and the hundreds of other Flow clones that state only entry 1's rule set.
  • Folk heuristics are not rules: fan-wiki tips such as “2×2 pools are not intended, so pretend they are illegal” are solver heuristics, not published rules, and were not counted as variants.
  • Not found — despite targeted searching: no verified published Flow-family game with moving endpoints, endpoints that must be visited in a prescribed order, moving blockers, a maximum path length, a no-touching rule, or a fill-target-percentage win. Absence here means “not found in this research”, not “does not exist” — these remain plausible invented dimensions, and the combinations total deliberately excludes them.
  • No booster-only entries: no entry in the catalogue is a mere power-up that changes no rule; entry 19's bridge claim is the closest, and it is flagged for exactly that reason.
