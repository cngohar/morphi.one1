## Known issues / choices

- Variant weights are equal (`1`) in the Memory manifest. The last served variant is excluded when alternatives are enabled; a sole enabled variant can repeat.
- No-preview retains the game's face-down arrival animation. Its timer begins with that arrival and its game-opening allowance is zero; the separately issued existing Card allowance is unchanged.
- Reaching the trios cap preserves the board and exposes the existing Home recovery path. It does not produce a win, result, saved completion or new loss flow.
- Moving stores only its logic-stream draw count in its concrete round; resume rebuilds it from seed and moves. Classic round serialization is unchanged.
- Scoring reuses the existing immutable tables: shared scope `memory`, independent scope `memory:trios`; no second scoring/config system or dependency was added. Default trio version is `memory-trios-v1`.
- Activity is prospective. No historical starts/first-flip records are backfilled; unknown played exits remain open. Later-saved completions without registered starts follow the owner's imported-completion definition.
- Browser admin checks append immutable score versions and audit rows. Cleanup restores the original coefficient values through new audited rollback versions, so local live version ids advance and previous live-board eligibility changes accordingly. Saved scores/history were not rewritten. An early fixture cleanup incorrectly rewound pointers; the local chains were repaired and the final test uses the existing audited rollback action.
- Detailed browser evidence uses desktop Chromium and viewport emulation, not physical phones. Physical-device validation remains outstanding.
- No known unresolved functional failure in the targeted checks. This is local implementation evidence, not owner acceptance or launch approval.
