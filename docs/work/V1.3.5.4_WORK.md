## Remaining limits and handoff

- A genuine same-ID local ranked checkpoint with different identity is discarded as a _resume choice_; server issuance and its lock survive. Local moves from that corrupted/stale checkpoint are intentionally not replayed. The original IndexedDB record is replaced by the next normal checkpoint or removed on explicit abandonment, never silently erased at read time. A stored session without a theme snapshot remains non-resumable through the existing conflict/takeover UI rather than being reconstructed with an invented look; old scored runs and retry hashes are unchanged.
- Solo offline checkpoints with a syntactically valid but unknown historical UUID score version can resume locally; the server remains authoritative and may reject a later submission if that version does not exist. Verifying arbitrary historical UUIDs offline would require new storage/network behavior and is **not** part of .4. Existing retry and save-status behavior applies.
- Compatibility and security rely on the pinned `memory-1`, unchanged classic JSON, server replay/score lookup, D1 authoritative issuance and immutable scoring versions. Future .5 rules cannot change an old variant meaning. Four existing variants remain the accepted catalogue; **zero** new presets implemented.
