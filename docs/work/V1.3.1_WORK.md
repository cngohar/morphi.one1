## Built

- Block Classic compatibility plus 10 × 10 board, Rows only and 60-second rush. Board size comes from the round; rows-only never clears or scores columns. Every variant retains the tray, piece supply, opening rule, no-fit ending and 300-placement cap. HUD, help, result and time-up ending use family-owned messages.
- Rush starts on the first valid placement, stops placements at zero, and keeps counting through Help, hidden pages, clear animations and reloads. Completion is queued before exit animation. Replay stays time-free; the new server rule applies the owner-approved ranked ceiling described below.
- Existing admin Games URL state now has cached stats cards and family rows, a live shared game header with a permission-aware switch, native confirmation dialog, explicit Tab/Shift+Tab containment, pending/failure handling and Escape focus return. Family summaries use the same per-variant cohorts; detail reads are scoped to their selected family. Delete/restore controls remain in Settings. Enable/resume for families and variants ignores any submitted reason and audits `Resumed by operator (no reason entered)`; disable validation is retained.
- Block scoring remains shared `brief-v1`, explained in its Settings editor. Test-play families derive from the catalog; protected/noindex test play can run a disabled Block variant without recording player persistence or statistics.
- The offline sound generator stages all output before replacing the manifest, preserves existing provenance and rolls back partial publication on failure. Three new processed static MP3s and provenance are present for audition. Memory trios uses `trio-match` with the existing streak pitch; moving uses one `reshuffle` after its mismatch hold; rush uses `timer-tick` during its last ten seconds. Existing mismatch/end actions and all Connect cues reuse their files. Runtime makes no ElevenLabs request.

The 42 implementation/test/asset paths are listed below. Five documentation files and two permanent evidence files complete this handoff. No dependency, route or migration was added.

## Decisions taken and pinned versions

- Keep classic `block-placement-1` output and the shared `brief-v1` scoring version. Variant ids/groups are family-owned data. The shared contract adds optional `maxSeconds`, optional checkpoint save time, optional result-ending text and per-variant nullable opening timing; no client score is trusted.
- The owner approved subtracting the fixed **3,000 ms Block entrance** and the **issued Card allowance (1,200 ms for new sessions)** from ranked issue-to-claim time, then enforcing an exact **62,000 ms** ceiling: 60 seconds plus two seconds for submission. Timed variants do not receive the existing additional one-second scoring allowance. Classic ranked timing is preserved. No new minimum duration was invented; reduced motion may skip the actual fixed opening animation.
- A legal nonempty rush replay prefix may finish without a full board/no-fit; move replay is time-free. This is the only new server rule, the elapsed ceiling, rather than per-move timestamps or a new first-move protocol.
- Stats use registered starts; imported guest completions have no matching start and stay outside Shown/Played. Unknown exits stay open; historical unknown leaderboard groups are not reassigned to current variants. All stored score rows remain available in the existing group/version table.
- The overview uses `CONFIG_CACHE` with a 60-second TTL and lifecycle-write deletion. A normal miss runs **7 D1 statements**, up to **10** if all three family lifecycle rows need insertion; a hit runs **0 aggregate statements**. Detail game reads run **7 + declared variant count**, scoped to that family. These counts exclude authentication, scoring and read-audit queries. Current mapping is **19 groups / 76 binds** against D1's 100-bind limit; its present implementation allows 25 groups before batching is needed.
- Existing ElevenLabs SDK `2.74.0`, `eleven_text_to_sound_v2`, `mp3_44100_128` and prompt influence `0.75` remain unchanged. New files trim leading silence at −60 dBFS, apply −3 dB gain, pad/trim to the requested duration, then encode mono MP3 at 44.1 kHz / 64 kbps; decoded checks enforce the limits. No dependency version changed; TypeScript remains pinned `~6.0.3`.

Current Cloudflare API documentation was checked for [KV reads](https://developers.cloudflare.com/kv/api/read-key-value-pairs/), [writes and minimum 60-second TTL](https://developers.cloudflare.com/kv/api/write-key-value-pairs/), [deletion](https://developers.cloudflare.com/kv/api/delete-key-value-pairs/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [prepared statements](https://developers.cloudflare.com/d1/worker-api/prepared-statements/) and [SQL](https://developers.cloudflare.com/d1/sql-api/sql-statements/). KV reads can retain cross-location stale values; enforcement/header state remains live D1.

## Known issues and risks

- Ranked issue-to-claim time includes idle time before the first valid placement, whereas the client clock starts with that placement. An otherwise valid countdown can exceed the server ceiling and be rejected. The owner explicitly accepted this limitation; no trusted first-move protocol was added.
- Time-free replay proves legal moves and scores, not individual move times or that a client waited until zero. There is no new minimum-duration rule. The server ceiling is the new ranked trust boundary and merits owner review.
- Live rush timing is monotonic; checkpoint restoration bridges time away using the saved wall-clock timestamp. Changing the system clock across a reload can affect that bridge.
- KV deletion/updates are eventually consistent and can leave another location's overview stale. The timestamp/TTL bounds display freshness; KV never authorizes new rounds or lifecycle writes. Cache failures fall back to D1 and are logged.
- The mapping's four binds per leaderboard group allow 25 groups; the current catalog has 19. Extend the mapping when the catalog exceeds that bound.
- Admin browser checks append immutable local scoring versions and audit records. Cleanup restores original coefficient values using audited rollback versions; live version ids/eligibility advance. Saved runs were not rewritten. The owner's concurrent gameplay and unrelated historical fixture rows were not deleted or reset.
- S5 audition and local owner acceptance remain open. Targeted automated passes do not imply physical-device acceptance, production readiness or a release approval.
