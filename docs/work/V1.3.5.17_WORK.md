## Root correction and preserved behavior

Games statistics and Memory Directory queried the first 101 score cohorts before
matching presets. With 243 issued leaderboard groups, an earlier preset with many
scoring versions could hide later presets' history despite exact nonzero totals.
The existing synthetic-100 test sliced an in-memory list and missed this D1 boundary.

The shared `queryScoreHistory` uses one JSON mapping parameter plus the family
parameter and native SQLite partitioned row numbering. Group selection precedes
the bound: each selected preset gets at most 101 cohorts for overflow detection,
then exposes the first 100. Games keeps its separate family 100-row summary and
existing overflow flag. Games selects the page before loading its history;
Directory selects history after filters/pagination and reuses the approved Games
truncation notice. Aggregate counts, immutable scoring versions, observed identities,
policy, permissions/audit, ranked replay and existing recovery remain intact.

Application files: `src/lib/server/{games,games-admin,memory-directory}.ts` and
`src/lib/components/MemoryDirectory.svelte`. Regressions:
`tests/integration/memory-variants.test.ts` and
`tests/e2e/memory-variants-admin.spec.ts`.
No rules, preset/group IDs, engine/scoring versions, schema, dependencies or
registry projections changed. No new controls or styling were introduced.
