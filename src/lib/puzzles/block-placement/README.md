# Block placement

Owns `logic.ts`, `manifest.ts`, `Game.svelte`, themes, and tests. It never imports another puzzle. Shared imports are the deterministic engine and common app presentation helpers.

Rules version remains `block-placement-1`: classic output, omitted-variant replays and existing vectors stay identical. Classic retains its original serialized round without `variant` or `boardSize`; absent size means eight. All variants keep three-piece trays, seeded nine-piece bags, opening fairness for ten placements and the 300-placement cap. `block:board-10` uses a 10×10 board; `block:rows-only` clears and scores rows only; `block:rush-60` uses the classic board and clears, ending after 60 seconds. Variants have separate leaderboard groups and share `brief-v1` scoring.

Rush starts on the first valid placement and continues through hidden pages, Help, clear animations and reloads. Runtime elapsed time is monotonic; checkpoint restoration bridges downtime using the checkpoint save timestamp, so a system-clock change during reload can affect that bridge. At the deadline, input stops and completion is queued before the existing clear/end animations. Replay stays time-free; the manifest accepts a legal, nonempty rush replay prefix even if placements leave room on the board. Replay cannot prove when individual moves occurred or that a client waited for the deadline. There is no new minimum-duration rule: fixed opening allowances can exceed the real presentation time under reduced motion, while the server still enforces the upper ceiling.

Ranked rush uses original issue-to-claim wall time minus the fixed three-second Block entrance and the issued Card allowance, with an exact two-second submission grace (reject above 62,000 ms). The usual one-second ranked scoring allowance is not added for timed variants. Idle time before the first placement still counts on the server and can reject an otherwise valid client countdown; this owner-approved limitation avoids a new trusted first-move protocol. Classic ranked elapsed behavior remains unchanged. No-fit and cap replays must remain terminal; all logs contain only legal placements and at most 300 moves.

The view records successful placements and queues a completed result as soon as the logic becomes terminal, before clear/end animations. Themes are cosmetic and never alter supply, placements, or scores. The owner-authorized local v1.1 slice supplies a resolved procedural theme for colors, cell/piece surfaces and spacing; pointer metrics use the actual themed grid gap. Theme versions/snapshots are separate from the game engine. The four legacy app themes remain for the guest build; documented verified anchors are used for procedural fallback. The shared generated symbol metadata is not painted onto Block pieces. Taste and the full v1.1 visual pass remain pending (`docs/work/V1.1_WORK.md`). The v1 selector draws the starting family from its injected RNG; Block-first was a first-test override removed by the owner on 2026-10-24.

Tests: local logic/theme tests, shared theme consistency, server integration, layout/input browser regressions, and cross-runtime vectors. `tests/vectors/block-cap.json` is a valid 300-placement benchmark workload (seed 784); it is a measurement input, not an independent scoring specification. The pre-existing seed-0/20-placement vector remains the independent scoring regression.
